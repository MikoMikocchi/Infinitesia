# Задачи рефакторинга

Архитектура и правила слоёв: `docs/ARCHITECTURE.md`. Конвейер планеты: `docs/05_PLANET_PIPELINE.md`.
Каждая задача самодостаточна: её можно отдать агенту отдельно. Ниже общие правила, затем задачи,
затем порядок и конфликты.

## Общие правила (для каждого агента)

**Сборка и проверка** (Windows, тулчейн CLion; `cmake` и `ninja` не в PATH):

```bash
export PATH="/c/Users/Miko/AppData/Local/Programs/CLion/bin/mingw/bin:/c/Users/Miko/AppData/Local/Programs/CLion/bin/ninja/win/x64:/c/Users/Miko/AppData/Local/Programs/CLion/bin/cmake/win/x64/bin:$PATH"
cd cmake-build-debug && cmake .. && cmake --build . && ctest
python tools/check_dependencies.py        # слои; тот же тест есть в ctest как LayeringCheck
```

Полный `ctest` идёт около минуты. Все тесты должны остаться зелёными. Предупреждений компилятора
быть не должно (`/W4` или `-Wall -Wextra` включены для модулей проекта).

**Слои** (зависимости только вниз): `foundation < chemistry, planet < geology < world < gameplay <
presentation < app`. Новый каталог в `src/` нужно внести в `MODULE_OF` и `ALLOWED`
(`tools/check_dependencies.py`) и в `CMakeLists.txt` (`infinitesia_add_module`).

**Нельзя:**
- коммитить (коммиты делает владелец);
- менять поведение, если задача про структуру. Для кода генерации планеты это значит **побитово
  одинаковый результат** (см. задачу 0);
- править файлы вне списка «Затрагивает» без причины;
- добавлять зависимости, которых нет в таблице слоёв.

**Параллельная работа.** Каждому агенту нужна отдельная копия репозитория (git worktree или
отдельная ветка). Конфликтующие задачи отмечены в разделе «Порядок».

**Отчёт.** Что сделано, какие файлы, результат `ctest` и `check_dependencies.py`, что осталось
и почему.

## Задача 0. Тест, фиксирующий результат генерации планеты (сделать первой)

**Зачем.** Все задачи по планете и геологии обязаны сохранять результат генерации. Сейчас это
проверялось одноразовой программой вне репозитория. Нужен постоянный тест.

**Что сделать.**
- `tests/PlanetGoldenTests.cpp` (+ цель в `CMakeLists.txt` с `doctest_discover_tests`).
- Для трёх планет (seed 1, 7, 12345; сетка 90×180; у seed 7 `axialTiltDegrees = 40`,
  `planetAgeYears = 2.0e9`) вычислить 64-битный FNV-1a хеш по всем полям каждой `PlanetRegion`,
  по `Province`, `PlanetWaterBalance` и числу эпох. Сравнить с константами в тесте.
- Значения на момент написания (на текущем коде, они обязаны совпасть):
  `seed 1: daaf4dc44249db9d`, `seed 7: 60fa8bba0fe37efb`, `seed 12345: 8f5a85d77d68589f`.
- Хешировать `double` по байтам, целые по 8 байт; порядок полей любой, но фиксированный.
- В комментарии: когда результат меняется намеренно, хеши пересчитывают и поднимают версию
  затронутой стадии (`PlanetStage::version`).

**Готово, когда:** тест проходит на текущем коде с указанными значениями; при изменении любого поля
в стадии он падает.

**Затрагивает:** `tests/`, `CMakeLists.txt`.

## Задача 4. Отвязать `GeologyModel` от `PlanetMap`

**Контекст.** `geology` лежит выше `planet`, потому что `GeologyModel(catalog, const PlanetMap&)`
читает карту. Это связывает слои и мешает тестам и инструментам.

**Что сделать.**
- В `geology` (или `planet`) ввести узкий интерфейс только с тем, что нужно модели: список
  `Province`, провинция по `ProvinceId`, `PlanetEpochTable`, нужные поля региона. Конструктор
  `GeologyModel` принимает его вместо `PlanetMap`; адаптер от `PlanetMap` живёт рядом с картой
  (или в `world/PlanetTerrainSource`).
- Существующий вызов `GeologyModel(catalog, map)` должен остаться рабочим (перегрузка/адаптер), чтобы
  не ломать `app`, `tools`, тесты; их можно перевести отдельно.
- Если после этого `geology` больше не включает ничего из `planet` кроме типов провинций/эпох —
  зафиксировать это в `ALLOWED` как минимально необходимое.

**Готово, когда:** `ctest` зелёный; `geology/model/*` не включает `planet/PlanetMap.h`.

**Затрагивает:** `src/geology/model/`, `src/world/PlanetTerrainSource.*`, места создания
`GeologyModel` (`app/Application.cpp`, `tools/`), `tools/check_dependencies.py`.
**Конфликтует с:** задача 5 (один и тот же `GeologyModel`). Делать до неё.

## Сознательно не делаем сейчас

- Объединение хеш-функций планеты (`Hash32`) и геологии (`GeologyRandom`): изменит результаты
  генерации.
- Выделение `presentation` в библиотеку: выигрыша в тестируемости почти нет.
- Планировщик систем с каденсами: появится, когда будет вторая тикаемая система.
- Перенос полей `PlanetRegion` в слои: делать по одному, когда соответствующая стадия
  переписывается, а не отдельной задачей.

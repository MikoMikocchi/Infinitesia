# Сетка мира: 250 × 250 theater tiles, 256 км

Документ фиксирует масштаб мира. Блок остаётся **1 м**; иерархия выше него —
степени двойки до театрального тайла и ровно 256 км на театр.

## 1. Иерархия

Dwarf Fortress: регион-тайл состоит из `16 × 16` local area blocks, каждый
local area block — из `48 × 48` тайлов. В Infinitesia один тайл — один блок
1 м, а local area block — `64 × 64` тайла: так чанк 16 м остаётся целым
делителем, а театральный тайл — ровно `64 × 64` чанка.

| Уровень | Формула | Размер | В чанках 16 м |
|---|---|---:|---:|
| Тайл / блок | `kBlockSizeMeters` | 1 м | — |
| Local area block | `64 × 64` тайлов | 64 м | `4 × 4` |
| Theater tile | `16 × 16` local blocks | **1024 м** | **`64 × 64`** |
| Theater | `250 × 250` theater tiles | **256 км** | — |

Площадь театра — **65 536 км²**. Это не вся планета: театр — локальное окно на
сфере. Планета остаётся отдельным, более грубым слоем с сеткой 360 × 720
(0.5°, ~55.5 км на экваторе).

Константы живут в `src/domains/natural/planetary/world/WorldMap.h`:

```cpp
inline constexpr int kTilesPerLocalBlock = 64;
inline constexpr int kLocalBlocksPerRegionTile = 16;
inline constexpr int kRegionTilesPerWorldSide = 250;

inline constexpr double kBlockSizeMeters = 1.0;
inline constexpr double kChunkSizeMeters = 16.0 * kBlockSizeMeters;
inline constexpr double kLocalBlockSizeMeters = kTilesPerLocalBlock * kBlockSizeMeters;
inline constexpr double kRegionTileSizeMeters = kLocalBlocksPerRegionTile * kLocalBlockSizeMeters;
inline constexpr double kWorldSizeMeters = kRegionTilesPerWorldSide * kRegionTileSizeMeters;
```

`kWorldGridVersion` повышается при любом изменении, которое двигает theater
tiles, сводки `RegionTile` или локальную решётку.

`PlanetId` (`src/core/PlanetId.h`) — адрес планеты в кампании. `Site::planet`
по умолчанию `kHomePlanet`. Пока планета одна, но театр, сайт и будущий сейв
уже могут включать её в ключ без переделки формата.

Иерархия масштабно-инвариантна по числам, но не по геймплею: подъём
`kBlockSizeMeters` до `2.44` даст DF-масштаб 481 км, но заодно растянет сайт с
1 км до 2.5 км, чанк с 16 м до 39 м и рабочего с 1.7 блока до 0.7 блока.
Поэтому размер блока выбирается по локальному геймплею, а не по карте.

## 2. RegionTile

`RegionTile` — компактная сводка на один theater tile, а не второй
`PlanetRegion`:

```cpp
struct RiverChannel
{
    float fromX, fromY;   // вход, нормализованные координаты плитки 0..1
    float toX, toY;       // выход (вниз по течению)
    float widthMeters;    // полная ширина водного зеркала
    float depthMeters;    // врезка в рельеф
    float bendX, bendY;   // контрольная точка Безье; <0 = прямой отрезок
};

struct RegionTile
{
    float elevationMeters;
    float temperatureCelsius;
    float precipitationMm;
    float drySeasonMonths;
    float soilFertility;
    float riverDischarge;      // 0..1
    float waterLevelMeters;    // уровень воды над морем
    float waterDepthMeters;    // глубина у центра плитки
    std::uint32_t riverFirst;  // срез WorldMap::Rivers()
    std::uint16_t riverCount;  // число сегментов русла в плитке
    std::int8_t flowEast;      // направление потока, -1/0/1
    std::int8_t flowNorth;
    Biome biome;
    std::uint8_t flags;        // ocean, lake, coast, river
    ProvinceId province;
};
```

Для моря `waterLevelMeters = 0`, а `waterDepthMeters` — глубина океана. Для
озера уровень — это уровень перелива из priority-flood, а глубина — насколько
впадина заполнена. Для реки уровень — поверхность воды в русле, а глубина —
врезка русла. У суши уровень совпадает с высотой, глубина равна нулю.

Русло плитки — это не один отрезок, а набор сегментов в общем массиве
`WorldMap::Rivers()`; `riverFirst`/`riverCount` задают срез для плитки. Если в
плитку впадает несколько притоков, каждый получает сегмент до общей точки
слияния в центре плитки, а из слияния выходит один общий сегмент вниз по
течению. Ширина притока считается по его водосбору, ширина общего сегмента —
по суммарному. Точки пересечения общей границы у соседних плиток совпадают,
поэтому сеть не рвётся на границе theater tile. `flowEast`/`flowNorth` хранят
направление стока вниз по течению.

Внутри плитки сегмент — квадратичная кривая Безье: `bendX/bendY` задают
контрольную точку. Амплитуда изгиба — до 18 % длины сегмента и не больше
0,12 плитки, направление берётся из детерминированного хэша координат плитки и
номера сегмента. Поэтому русло изгибается, но остаётся внутри своего theater
tile и не рвётся на границах. `WorldTerrain::WaterAt` и врезка рельефа считают
расстояние уже до кривой, а не до прямой.

`WorldMap` хранит `250 × 250` таких записей — **62 500** ячеек, около
**3 МиБ** — и `LocalGrid`, задающий положение окна на сфере. Театры кэширует
`TheaterCache` (`world/`): LRU по `TheaterKey { PlanetId, PlanetCellId }`,
промах генерируется на рабочем потоке, повторный вход в область — попадание.
Просмотрщик показывает preview-театр, а активный театр сайта не меняется от
кликов по глобусу. **Theater Map** — основной экран выбора: 250 × 250 тайлов
целиком, с контуром
окна театра на глобусе. `W` переключает Theater Map и планетарную карту; `R`
открывает сайт как приближение выбранного тайла. `RegionTileId`
это `{i, j}` от центрального тайла `(0, 0)`, диапазон `-125 .. 124`.

## 3. Генерация

`WorldGenerator` берёт готовый `PlanetMap` и `RegionTerrain`:

1. для каждого theater tile считать точку на сфере через `LocalGrid`;
2. взять планетарные поля (`PlanetSurface`) и крупный рельеф;
3. добавить детали рельефа до длины волны `2 × 1024 = 2048 м`;
4. пересчитать температуру по локальной высоте (lapse rate `6.5 K/км`);
5. применить локальный климат (`world/WorldClimate.{h,cpp}`): крупные
   водоёмы смягчают температуру побережья, континентальность даёт холодные
   зимы внутри материка, а преобладающие ветры переносят океаническую влагу,
   поднимают её на наветренных склонах и оставляют дождевую тень за хребтом;
6. выставить флаги `Ocean` и `Lake`.

Вода и климат считаются в два прохода: сначала `WorldHydrology` даёт локальные
озёра и реки, затем `WorldClimate` видит эти водоёмы и меняет температуру и
осадки, после чего `WorldHydrology` пересчитывает воду уже по локальным осадкам.
`WorldHydrology` (`world/WorldHydrology.{h,cpp}`) считает локальную воду
на 250 × 250:

1. priority-flood заполняет замкнутые впадины до уровня перелива;
2. каждая суша направляет сток к самому низкому соседу (8 направлений);
3. водосбор накапливается вниз по течению с весом по осадкам;
4. тайлы с эффективным водосбором ≥ `kRiverAreaKm2` становятся реками;
5. впадины глубже `kLakeDepthMeters` становятся озёрами;
6. для каждого озера записывается уровень перелива и глубина, для каждой реки —
   направление стока, ширина/глубина русла и отрезок русла внутри плитки.

После гидрологии биомы классифицируются заново по локальным температуре,
осадкам и водосбору, а `MarkCoasts` выставляет флаги `Coast`.

Локальные потребители читают мир через `WorldTerrain`
(`region/WorldTerrain.{h,cpp}`): внутри окна он подменяет базовую высоту,
температуру, осадки, сухой сезон, плодородие, провинцию и воду на значения
`RegionTile`, а мелкий рельеф по-прежнему добавляет `RegionTerrain`. Вне окна
он возвращается к планетарным полям. Непрерывные поля между центрами region
tiles смешиваются bilinear/smoothstep (`WorldMap::SampleAt`), поэтому на границе
тайлов нет ступеньки высоты и полосы в затенении; биом, провинция, флаги и
гидрология берутся из ближайшего тайла.

`WorldTerrain::WaterAt` отдаёт уровень, глубину, направление потока, врезку
русла и подъём берега в точке. `SettlementTerrain` заполняет водой локальные
впадины озёр до уровня перелива и речные русла — вода появляется только там,
где дно ниже её поверхности. `WorldTerrain::ElevationMeters` вычитает врезку
русла и прибавляет подъём берега, поэтому река лежит в настоящей ложбине с
берегами, а не поверх земли.

Берег канала всегда стоит выше воды: если природный берег ниже поверхности
реки, он поднимается (естественная левея), если выше — не трогается. Гребень
поднят больше чем на один блок над водой, поэтому даже полностью заполненная
верхняя клетка жидкости не выходит за него. Внутри воды дно опускается до
`поверхность - depth`, у кромки остаётся короткий откос до уровня воды, а сухой
берег сначала поднимается до гребня, а затем плавно растворяется в природном
рельефе на широкой долине (примерно две ширины берега с каждой стороны). Это
повторяет подход Dwarf Fortress: река — это врезанное русло с берегами и
долиной, а не лужа в рельефе. Река остаётся обычной жидкостью: если прокопать
берег, вода пойдёт в проём, как и должно быть в DF; удерживает её рельеф, а не
запрет обмена.

Ширина русла растёт как корень из водосбора и мягко насыщается: формула
`raw * 40 / (raw + 40)`, где `raw = 2.5 * sqrt(площадь)`. Асимптота — **40 м**,
половина насыщения — при `raw = 40` (водосбор около 256 км²). Поэтому крупная
река DF-масштаба получается только при очень большом водосборе, а притоки и
главное русло сохраняют разницу в ширине.

`FluidField` питает реку с **верхнего конца**: только верхние клетки на входе
(там, где сосед в направлении против потока отсутствует или не является рекой)
получают `sourceAmountMb`. Остальные клетки наполняются течением; поэтому
плотина действительно перекрывает низовье, а не оставляет его бесконечным
источником. Вода дополнительно переносится вниз по `flowEast/flowNorth` — без
этого односторонний источник слишком медленно доходит до устья.

Открытая граница тоже направленная. Внешнее кольцо локальной сетки и море
являются стоками только для воды, которая течёт **наружу** (или в море): река,
идущая вдоль края или вдоль берега, не режется невидимой границей. Верхний край
с током внутрь — источник, нижний — сток. Стоку удаляется вода, но клетка
сохраняет признак русла и приток сверху: в том же тике она наполняется снова, и
река доходит до края, а не заканчивается сухой полосой. Море после всех
перемещений пополняется до полного уровня, поэтому у устья нет постоянной
впадины. Край загруженных чанков стоком не является: иначе при выгрузке чанка в
реке появлялись бы дыры по сетке чанков.

Вблизи границы theater tile `WaterAt` смотрит русла не только своей, но и соседних
плиток (в пределах ширины долины). Поэтому река, пересекающая угол четырёх
плиток, не обрывается по границе: вода и берега продолжаются через угол.

Признак `FluidCell::river` отделяет русло от происхождения жидкости: он
сохраняется, когда клетка осушается или в неё ставят блок, поэтому вынутый блок
не оставляет вечную дыру, а вода может вернуться. Давление при этом не может
проходить через речные клетки и не может брать их как цель: иначе море или озеро
использовало бы полную реку как трубу и телепортировало воду в берег. Обычное
течение и гравитация через русло работают, поэтому прорыв берега и водопад —
это нормальное поведение, а не особая ошибка. Боковой выход разрешён в своё
русло, в выкопанную клетку, вниз и вниз по течению при сухом перепаде; тонкая
плёнка по естественному воздуху сбоку запрещена — именно она раньше заползала
на берег.

`PlanetTerrainSource::FluidAt` переносит это в `FluidColumn`, а `FluidField`
инициализирует клетки водой с `FluidOrigin::River`/`Lake`/`Sea` и направлением
потока. `RegionMapView` тоже запрашивает `WaterAt` для каждого пикселя карты,
поэтому реки и озёра видны на карте региона как вода, а не только как
врезанные ложбины.

```cpp
PlanetMap planet(parameters);
WorldGenerator generator(planet);
WorldMap world = generator.Generate(GeographicCoordinates{45.0, 30.0});

const RegionTile &centre = world.At(0, 0);
const RegionTile &east = world.At(1, 0);
```

## 4. Что ещё не сделано

- `LocalGrid` приведён к theater tile 1024 м; `RegionData` — 65 × 65 точек по
  16 м (64 × 64 чанка).
- Планетарная сетка 360 × 720 (0.5°, ~55.5 км на экваторе) остаётся: её нужно
  не огрублять, а облегчить структуру `PlanetRegion` (месячные массивы — в
  side table, `float` вместо `double`).
- `WorldMap` уже используется `RegionGenerator` и `SettlementTerrain`:
  внутри окна высота, климат, почва и провинция берутся из theater tile.
- Показ театра в просмотрщике сделан (`WorldMapView`); остаётся политический
  слой и сайты.

## 5. Порядок внедрения

1. `WorldMap` и `WorldGenerator` (сделано).
2. `LocalGrid` → 1024 м, `RegionData` → 64 × 64 чанка (сделано).
3. Локальная гидрология мира: реки и озёра на 250 × 250 (сделано).
4. `RegionGenerator` читает климат/провинции/высоту из `WorldMap` (сделано).
5. Локальный климат и дождевые тени на 250 × 250 (сделано).
6. Облегчить `PlanetRegion`, не меняя сетку 360 × 720.
7. Политический слой театра и сайты.

# Модель данных: Infinitesia ↔ Dwarf Fortress

Документ описывает, какие сущности и данные есть в Dwarf Fortress (по описаниям из `df-structures` и коде DFHack), как они соотносятся с текущей моделью Infinitesia и что стоит добавить/преобразовать, чтобы проект стал полноценно data-driven, как DF.

## 1. Как данные устроены в Dwarf Fortress

DF — закрытый C++-бинарник без открыого API. DFHack инжектится в процесс DF и читает/пишет память напрямую.

- **df-structures** (`library/xml` в dfhack, репозиторий `DFHack/df-structures`) — XML-файлы `df.*.xml`, описывающие layout каждой структуры игры (поля, типы, смещения, enum, наследование, ссылки `ref-target`).
- Из XML генерируются C++ заголовки (`library/include/df/*.h`) и метаданные для Lua-обёртки.
- `symbols.xml` — абсолютные адреса глобальных объектов и vtable DF; загружается в рантайме, не требует перекомпиляции.
- **Raws** (текстовые файлы модов `raw/objects/*.txt`) парсятся при загрузке и превращаются в in-memory C++ структуры.
- Вся игра — один большой граф в памяти, укоренённый в `df::global.world`.

| `assets/biology/species.json` — виды растений | `df.plant_raw`, `df.creature_raw` | У вас есть ниша, размеры, материалы частей, урожайность. Можно расширить на животных и монстров, добавить касты, тела, ткани, части тела, атаки. |
| `src/domains/natural/biology/Species.h`, `SpeciesCatalog.h` | Каталог видов существ | Каталог определений (raws). Нужно отделить определение вида от экземпляра в мире. |

| `src/gameplay/items/Item.h`, `assets/gameplay/items.json` — стопки предметов | `df.item`, `df.itemdef` | У вас есть ItemDef и Item. В DF добавляются типы предметов, качество, износ, содержимое контейнеров. |

## 3. Какие данные вообще есть в Dwarf Fortress (полный список)

### Мир и география
- **Мир** (`world`) — весь сгенерированный мир
- **Регион** (`region`) — часть мира с биомом, климатом, дикостью
- **Поселение / Сайт** (`site`, `world_site`) — деревня, крепость, крепость игрока
- **Блок карты** (`map_block`) — 16×16 тайлов на одном z-уровне
- **Тайл** (`tiletype`) — земля, стена, пол, постройка, жидкость

### Материалы и геология
- **Материал** (`material`, `matgloss`) — дерево, кожа, кость, шерсть, кровь и т.д.
- **Неорганический материал** (`inorganic_raw`) — камень, руда, глина, песок, магма
- **Растение** (`plant_raw`) — деревья, кусты, культуры

### Существа и жизнь
- **Вид существа** (`creature_raw`) — определение вида из raws (тело, ткани, атаки)
- **Юнит / Существо** (`unit`) — живое создание в игре (дворг, зверь, враг)
- **Душа** (`soul`) — навыки, атрибуты, черты характера, эмоции
- **Часть тела / Ткань** (`body_parts`, `tissue_layer`) — кожа, мышца, кость, органы, ранения

### Предметы и крафт
- **Предмет** (`item`) — любой предмет: оружие, еда, мебель, монета, труп
- **Тип предмета** (`itemdef`, `item_type`) — класс предмета
- **Постройка** (`building`) — мастерская, стокпайл, комната, ловушка
- **Тип постройки** (`building_def`) — определение вида постройки из raws
- **Задача** (`job`) — действие юнита (копать, переносить, крафтить, есть, спать)
- **Рецепт крафта** (`reaction`) — что делает мастерская (плавить руду, шить, готовить)

### Цивилизации и история
- **Цивилизация** (`historical_entity`, `entity`) — гномы, гоблины, люди, эльфы и т.д.
- **Историческая личность** (`historical_figure`) — конкретное существо с именем и биографией
- **Историческое событие** (`history_event`) — битва, подвиг, создание артефакта
- **Артефакт** (`artifact`) — уникальный предмет с именем и историей

### Магия, яды, взаимодействия
- **Взаимодействие** (`interaction`) — секреты, божественные силы, яды, превращения
- **Синдром** (`syndrome`) — отравление, болезнь, проклятие

### Интерфейс и язык
- **Язык** (`language`) — язык цивилизации, таблицы слов, генерация имён
- **Отряд** (`squad`) — военный отряд
- **Нора** (`burrow`) — зона для задач и ограничения движений
- **Зона цивилизации** (`civzone`) — склад, пастбище, трапезная, храм, тронная комната

## 4. Рекомендации по преобразованию Infinitesia

### Разделить определение и экземпляр
- **Def / Raw** (неизменяемый каталог): `MaterialDef`, `SpeciesDef`, `ItemDef`, `ObjectKindDef`, `ReactionDef` — читаются из JSON/реистров, живут вечно.
- **Instance** (изменяемое состояние в мире): `Unit` (живое с душой, задачей, инвентарём), `Item` (предмет с материалом, качеством, содержимым), `Building` (постройка на клетке), `Job` (задача со списком требований).

### Добавить новые домены
- `domains/society/` — цивилизации, отношения, этика, языки.
- `domains/gameplay/` — задачи (`Job`), рецепты крафта, зоны, нора.
- `domains/history/` — события мира, исторические личности, артефакты.

### Усилить блоки и тайлы
- Ввести понятие тайла внутри блока (жидкость, спаттер, температура, освещение).
- Связать `Chunk → Block → Tile` иерархически, как в DF (`map_block_column → map_block → tile`).

### Связи между сущностями
- Каждый `Unit` ссылается на `SpeciesDef` (вид), имеет `pos` (координаты), инвентарь (`Item`), текущий `Job`, `Soul` (навыки).
- Каждый `Item` ссылается на `MaterialDef` и `ItemDef`, может содержать другие предметы (контейнеры).
- Каждый `Job` ссылается на список необходимых `Item` и материалов, как `job_item` в DF.

### Data-driven природа
- Почти всё задаётся через ассеты (JSON/реистры), как raws в DF.
- Модер должен иметь возможность добавить новый камень, дерево, рецепт или синдром, просто дописав файл, без перекомпиляции движка (только если изменится layout структур — тогда перекомпиляция, как в DFHack).

# Модель данных: Infinitesia ↔ Dwarf Fortress

Документ описывает, какие сущности и данные есть в Dwarf Fortress (по описаниям из `df-structures` и коде DFHack), как они соотносятся с текущей моделью Infinitesia и что стоит добавить/преобразовать, чтобы проект стал полноценно data-driven, как DF.

## 1. Как данные устроены в Dwarf Fortress

DF — закрытый C++-бинарник без открыого API. DFHack инжектится в процесс DF и читает/пишет память напрямую.

- **df-structures** (`library/xml` в dfhack, репозиторий `DFHack/df-structures`) — XML-файлы `df.*.xml`, описывающие layout каждой структуры игры (поля, типы, смещения, enum, наследование, ссылки `ref-target`).
- Из XML генерируются C++ заголовки (`library/include/df/*.h`) и метаданные для Lua-обёртки.
- `symbols.xml` — абсолютные адреса глобальных объектов и vtable DF; загружается в рантайме, не требует перекомпиляции.
- **Raws** (текстовые файлы модов `raw/objects/*.txt`) парсятся при загрузке и превращаются в in-memory C++ структуры.
- Вся игра — один большой граф в памяти, укоренённый в `df::global.world`.

## 3. Какие данные вообще есть в Dwarf Fortress (полный список)

### Мир и география
- **Мир** (`world`) — весь сгенерированный мир
- **Регион** (`region`) — часть мира с биомом, климатом, дикостью
- **Поселение / Сайт** (`site`, `world_site`) — деревня, крепость, крепость игрока
- **Блок карты** (`map_block`) — 16×16 тайлов на одном z-уровне
- **Тайл** (`tiletype`) — земля, стена, пол, постройка, жидкость

### Материалы и геология
- **Материал** (`material`, `matgloss`) — дерево, кожа, кость, шерсть, кровь и т.д.
- **Неорганический материал** (`inorganic_raw`) — камень, руда, глина, песок, магма
- **Растение** (`plant_raw`) — деревья, кусты, культуры

### Существа и жизнь
- **Вид существа** (`creature_raw`) — определение вида из raws (тело, ткани, атаки)
- **Юнит / Существо** (`unit`) — живое создание в игре (дворг, зверь, враг)
- **Душа** (`soul`) — навыки, атрибуты, черты характера, эмоции
- **Часть тела / Ткань** (`body_parts`, `tissue_layer`) — кожа, мышца, кость, органы, ранения

### Предметы и крафт
- **Предмет** (`item`) — любой предмет: оружие, еда, мебель, монета, труп
- **Тип предмета** (`itemdef`, `item_type`) — класс предмета
- **Постройка** (`building`) — мастерская, стокпайл, комната, ловушка
- **Тип постройки** (`building_def`) — определение вида постройки из raws
- **Задача** (`job`) — действие юнита (копать, переносить, крафтить, есть, спать)
- **Рецепт крафта** (`reaction`) — что делает мастерская (плавить руду, шить, готовить)

### Цивилизации и история
- **Цивилизация** (`historical_entity`, `entity`) — гномы, гоблины, люди, эльфы и т.д.
- **Историческая личность** (`historical_figure`) — конкретное существо с именем и биографией
- **Историческое событие** (`history_event`) — битва, подвиг, создание артефакта
- **Артефакт** (`artifact`) — уникальный предмет с именем и историей

### Магия, яды, взаимодействия
- **Взаимодействие** (`interaction`) — секреты, божественные силы, яды, превращения
- **Синдром** (`syndrome`) — отравление, болезнь, проклятие

### Интерфейс и язык
- **Язык** (`language`) — язык цивилизации, таблицы слов, генерация имён
- **Отряд** (`squad`) — военный отряд
- **Нора** (`burrow`) — зона для задач и ограничения движений
- **Зона цивилизации** (`civzone`) — склад, пастбище, трапезная, храм, тронная комната

## 4. Рекомендации по преобразованию Infinitesia

### Разделить определение и экземпляр
- **Def / Raw** (неизменяемый каталог): `MatterDef`, `SpeciesDef`, `ItemDef`, `ObjectKindDef`, `ReactionDef` — читаются из XML/реестров, живут вечно.
- **Instance** (изменяемое состояние в мире): `Unit` (живое с душой, задачей, инвентарём), `Item` (предмет с материалом, качеством, содержимым), `Building` (постройка на клетке), `Job` (задача со списком требований).

### Добавить новые домены
- `domains/society/` — цивилизации, отношения, этика, языки.
- `domains/gameplay/` — задачи (`Job`), рецепты крафта, зоны, нора.
- `domains/history/` — события мира, исторические личности, артефакты.

### Усилить блоки и тайлы
- Ввести понятие тайла внутри блока (жидкость, спаттер, температура, освещение).
- Связать `Chunk → Block → Tile` иерархически, как в DF (`map_block_column → map_block → tile`).

### Связи между сущностями
- Каждый `Unit` ссылается на `SpeciesDef` (вид), имеет `pos` (координаты), инвентарь (`Item`), текущий `Job`, `Soul` (навыки).
- Каждый `Item` ссылается на `MatterDef` и `ItemDef`, может содержать другие предметы (контейнеры).
- Каждый `Job` ссылается на список необходимых `Item` и материалов, как `job_item` в DF.

### Data-driven природа
- Почти всё задаётся через ассеты (XML/реестры), как raws в DF.
- Модер должен иметь возможность добавить новый камень, дерево, рецепт или синдром, просто дописав файл, без перекомпиляции движка (только если изменится layout структур — тогда перекомпиляция, как в DFHack).

## 5. Материалы DF ↔ материя Infinitesia

DF хранит материю в двух raws: `df.material.xml` (дерево, кожа, кость, шерсть, кровь, ткани, сплавы — всё, что описывается шаблонами `material_template`) и `df.matgloss.xml` (`inorganic_raw` — камни, руды, глины, пески, магма; `plant_raw` — деревья, кусты, культуры). Наш единый каталог `assets/matter/matter.xml` (`MatterDef`) покрывает обе роли: воздух, жидкости, породы, минералы и строительная материя — в одном списке с плотными `MatterId`.

### 5.1. Сравнение полей

| Свойство | DF | `MatterDef` (наш) | Вывод |
|---|---|---|---|
| Плотность | `solid_density` + `liquid_density` | одна `density` | нужны обе (твёрдая и жидкая), иначе расплавы и вода теряют точность |
| Теплоёмкость | `spec_heat` | нет | добавить `specHeat` |
| Температуры фаз | `melting_point`, `boiling_point`, `ignite_point`, `mat_fixed_temp`, `heatdam_point`, `colddam_point` | нет | главный пробел: без них нет плавки, литья, огня, закалки |
| Молярная масса | `molar_mass` | `molarMass` (`ChemistryInfo`) | ок |
| Прочность | `yield`, `fracture`, `strain_at_yield[]`, `absorption`, `max_edge` | `digClass`, `mohs` (`ChemistryInfo`) | `digClass` — грубая замена; для крафта и боя нужны отдельные прочности |
| Цвет, имя, прилагательное | `state_color`, `state_name`, `state_adj` по каждому `matter_state` (solid/liquid/gas/powder) | один `color` + `opacity`/`emission` | у нас проще: одно состояние. Для пара/пыли/расплава придётся добавить цвета и имена по состояниям |
| Оптическое | `mat_state` (opacity/emission по состояниям) | `opacity`, `emission` (по каналам) | ок, даже детальнее |
| Ценность | `material_value` | нет | добавить `value` (нужна экономике и торговле) |
| Флаги | `material_flags`, `inorganic_flags` (десятки битов: `ITEMS_*`, `DEEP_SPECIAL`, `METAL_ORE`, `SOIL`, …) | `tags` (класс `ClassTag` всегда) | у нас гибче (строковые теги), но нет готовых меток: металл, руда, ткань, древесина, кость, волокно |
| Руда → продукт | `metal_ore { mat_index, probability }`, `economic_uses` | нет | добавить: выход металла и экономические применения |
| Сплав | `material_template` + состав из `reaction_product` | класс `built`, тег | нет описания состава сплава — добавить рецептуру |
| Появление в мире | `environment`, `environment_spec` (где и как материал встречается) | только `ModalComposition` (доля минерала в породе) | добавить правила появления (жилы, слои, кластеры) |
| Реакции с материей | `reaction_product`, `hardens_with_water`, `reaction_class` | нет | добавить `hardensWithWater` и `reactionClass` (гипс, цемент, известь) |
| Растительные материи | `plant_raw.material_defs` (материи частей: древесина, лист, плод) | класс `plant` + `species.json` (`matter.trunk = "oak.trunk"`) | частично: связь вид→материя есть, но материя растения не шаблонизируется от `plant_raw` |

### 5.2. Где мы сильнее

- **Единый плотный каталог**: одна запись `MatterDef` и один `MatterId (uint16)` на всё (воздух, вода, порода, минерал, постройка). В DF — три разных raws и разные индексы (`mat_index`, `inorganic.index`, `plant.index`).
- **Явная `Provenance`**: видно, откуда определение пришло (природа, стройка, геймплей).
- **Боковые таблицы**: `ChemistryInfo` и `ModalComposition` держат редкие поля отдельно, не раздувая основной рекорд.
- **Теги вместо битовых флагов**: правила спрашивают «это вода?» по тегу, а не по номеру материала.

### 5.3. Что заимствовать (приоритет)

1. **Температуры и теплоёмкость** (`melting_point`, `boiling_point`, `ignite_point`, `spec_heat`, `mat_fixed_temp`, `heatdam`/`colddam`): без них нет плавки, литья, огня, погоды.
2. **Прочность** (`yield`, `fracture`, `strain_at_yield`, `absorption`, `max_edge`): крафт, бой, разрушение.
3. **Рудные метки и `metal_ore`**: метка «руда» + продукт-металл с `probability`, чтобы из минерала-руды получать металл.
4. **`material_value`**: ценность материала для экономики и торговли.
5. **`environment`-правила**: где материал появляется (жилы, слои, кластеры), а не только доля в породе.
6. **`hardens_with_water` / `reaction_class`**: схватывающиеся и реагирующие материалы (гипс, цемент, известь).
